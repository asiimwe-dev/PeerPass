[`architecture.md`](./architecture.md). It keeps the Flutter client, FastAPI
service, database migrations, and tests independently deployable while leaving
room for future LMS and institutional integrations.

`docs/Contribution.md` is the canonical contribution guide.

The Flutter scaffold (platform runners, package metadata, assets, and tests) is
kept in `frontend/`.

Backend tool-generated files are also intentionally deferred. Run
`alembic init alembic` from `backend/` to create `alembic.ini`, `alembic/env.py`,
`alembic/script.py.mako`, and the `alembic/versions/` directory when database
development begins. Migration files should then be created with
`alembic revision --autogenerate -m "describe change"`.

## Dependency direction

Routes depend on schemas and services. Services depend on models and core
interfaces, not on HTTP or Flutter. Flutter features depend on shared core
utilities and the REST API, while domain decisions remain in the backend.

## Initial delivery order

1. Establish configuration, database session management, and migrations.
2. Add identity, course units, competencies, sessions, and ratings.
3. Implement validation before exposing tutor matching.
4. Add session lifecycle and incentive aggregation.
5. Build Flutter flows against the stable API contracts.
